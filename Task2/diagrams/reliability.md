# Стратегия обеспечения надёжности архитектуры ИС AdScale

Для обеспечения целевых показателей SLA (99.9%) и стабильной работы при нагрузке до 50 000 RPS, в архитектуре AdScale внедряются следующие паттерны:

1. **Паттерн Retry** – повторные запросы, нужны для сглаживания кратковременных сетевых сбоев. Важно – для операций **записи** Retry применяется только когда обеспечена идемпотентность операций (например операция пополнения бюджета через платежный шлюз).

   a. API Gateway → Ad Service, Ad Service → RTB Service, RTB Service → Delivery Service – стратегия: экспоненциальный backoff с джиттером – стандарт для систем с жесткими требованиями к SLA  
   b. Campaign Service → Платежный шлюз, API Gateway → Analytics Service, API Gateway → Campaign Service – стратегия: экспоненциальный backoff

2. **Паттерн Circuit Breaker** – автоматическое выключение запросов на недоступный сервис с целью экономии ресурсов с автоматической периодической проверкой доступности и обратного плавного включения обращений к сервису.

   a. На уровне API Gateway – при маршрутизации запросов к внутренним сервисам: **Campaign Service, Ad Service, Delivery Service, Analytics Service.**  
   b. В коде приложений **Ad Service** и **RTB Service**, т.к. основной критичный процесс (**Ad Service** → RTB Service → **Delivery Service**) проходит через синхронные АПИ (не через Gateway) и по сути должен быть отказоустойчивым.

3. **Резервные стратегии** – применяются совместно при недоступности какого-то сервиса

   a. Самый критичный сервис RTB – при недоступности Redis автоматически переключается на чтение кампаний, правил и бюджетов из Read-реплики **Campaign DB по gRPS**  
   b. Т.к. события и клики – важно при списании оплаты с рекламодателя, события не должны теряться – если Kafka недоступна – то **Delivery Service сохраняет полученные события показов и кликов локально в бефере и отправляет их после восстановления Kafka.**  
   c. Если сервис доставки не может получить банер из базы изображений для кампании победителя – он возвращает некоторый дефолтный банер в ответ (есть небольшой список настроенных fallback-кампаний)
